# Корпоративный слой: стартовый набор

Дата: 21 марта 2026
Статус: максимально прикладной starter kit для корпоративного AI pilot

## 1. Что такое корпоративный слой

корпоративный слой превращает курс в управляемый корпоративный продукт.

Без него компания покупает видео и надежду.
С ним компания покупает:
- безопасный для пилота рамки использования AI;
- набор стартовых сценариев;
- назначенного owner и понятный порядок решений;
- общий шаблон, общий чек-лист и короткий отчет;
- решение по следующей волне.

## 3. Pilot-safe usage rules

### Green zone: можно использовать в первой волне

| Сценарий | Условие |
|---|---|
| Черновики писем и сообщений | без персональных и чувствительных данных |
| Summary обезличенных документов | финальная версия проходит human review |
| Подготовка к встрече | без выгрузки закрытых материалов клиента |
| Внутренние черновики, планы, структуры | финальный владелец текста известен |
| Первичный ресерч темы | результат не принимается как факт без проверки |

### Yellow zone: только с human review и owner approval

| Сценарий | Ограничение |
|---|---|
| Внутренние документы с рабочими данными | только после обезличивания |
| Клиентские формулировки | обязательна ручная редактура |
| Summary по операционным данным | нельзя отправлять чувствительные поля |
| Подготовка управленческих выводов | AI не выдает финальное решение |

### Red zone: не берем в первую волну

| Сценарий | Почему исключаем |
|---|---|
| Персональные данные без согласованной политики | риск compliance и privacy |
| Финальные договоры и юридически значимые тексты | слишком высока цена ошибки |
| Финансовые выводы без отдельной валидации | высокий риск фактической ошибки |
| Конфиденциальные документы без approved policy | нельзя запускать в безопасный для пилота контуре |

## 4. Стартовая библиотека сценариев

Для первого пилота достаточно `5` сценариев. Больше не нужно.

| Сценарий | Тип выхода | Для каких ролей | Какой сигнал полезности смотрим |
|---|---|---|---|
| Follow-up после встречи | письмо или summary | sales, ops, project roles | скорость подготовки и полнота follow-up |
| Summary документа | краткое резюме и action points | managers, analysts, ops | сокращение времени на первичный разбор |
| Подготовка к встрече | agenda, вопросы, тезисы | managers, account roles | качество подготовки и полнота вопросов |
| Внутренний черновик сообщения | письмо, memo, update | team leads, specialists | скорость старта и меньше пустых черновиков |
| Первичная карта темы | structured note | marketing, product, strategy | качество первого драфта и структура |

Правило отбора:
- сценарий должен быть повторяемым;
- выход должен быть видимым;
- риск должен быть умеренным;
- результат должен проходить human review без сложной внешней системы.

## 5. Роли в пилоте

| Роль | Что делает до старта | Что делает во время пилота | Что делает после пилота |
|---|---|---|---|
| Business owner | утверждает группу, сценарий и рамки | участвует в midpoint и снимает блокеры | принимает решение по wave 2 |
| Functional manager | помогает выбрать сценарии использования | смотрит на применение внутри команды | подтверждает, что сценарий реально живой |
| Participants | проходят Session 0 и домашние | собирают шаблоны и mini-projects | фиксируют repeatable scenarios |
| Course side | дает базовый модуль и управляющую логику | собирает метрики и shared artifacts | готовит report и recommendation |

## 6. План пилота по дням

| Период | Что делаем | Какие артефакты должны появиться |
|---|---|---|
| До дня 0 | owner alignment и rules setup | бриф владельца, team rules, cohort list |
| День 1-2 | Session 0 и первая практическая победа | первая практическая победаs и сравнение до / после |
| День 3-5 | выбор и уточнение сценарии использования | use-case map и первые шаблоны |
| День 6-9 | midpoint-check | промежуточный signal: что работает, где трение |
| День 10-14 | shared artifact assembly | общий шаблон, общий чек-лист, mini-projects |
| День 15-19 | финальный review | pilot report и решение по wave 2 |

## 7. Что компания должна получить на выходе

Минимальный corporate-ready output:
1. обученную группу с видимым activation;
2. `1` общий сценарий;
3. `1` общий шаблон;
4. `1` общий чек-лист;
5. короткий pilot report;
6. одно управленческое решение на следующий шаг.

Для пакета `Core Rollout` к этому добавляются:
1. `3-5` утвержденных сценариев;
2. стартовый набор правил команды;
3. план следующей волны на `30-45` дней.

## 8. Decision gates

### Scale

Идем в scale, если одновременно:
- Session 0 completion `>= 75%`;
- Первая практическая победа rate `>= 65%`;
- есть общий сценарий, template и checklist;
- owner подтверждает, что пилот дал понятный сигнал.

### Improve

Идем в improve, если:
- early value есть;
- но completion, homework flow или scope собраны с трением;
- owner видит потенциал, но не готов масштабировать текущую конфигурацию.

### Narrow

Идем в narrow, если:
- общая программа широка;
- но один сценарий использования или одна роль показывает сильный эффект.

### Stop

Идем в stop, если:
- activation низкий;
- первая практическая победа почти не появляется;
- shared artifacts не собираются;
- owner не может объяснить, что именно улучшилось.

## 9. Что не входит в корпоративный слой первой версии

Не входит:
- enterprise governance;
- кастомные AI-интеграции;
- procurement и vendor security process;
- cross-functional rollout сразу на несколько функций;
- юридическая экспертиза клиентских политик.

## 10. Когда корпоративный слой можно считать собранным

корпоративный слой рабочий, если:
1. sales может продать его без устной импровизации;
2. owner понимает, что компания покупает на выходе;
3. pilot заканчивается конкретными shared artifacts;
4. по итогам можно принять решение без слов "в целом было интересно".
