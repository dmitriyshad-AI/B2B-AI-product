# Пакет отчетности для ЛПР

Дата: 22 марта 2026
Статус: standalone пакет документов, который owner может переслать ЛПР без устной расшифровки

## 1. Что должно уйти ЛПР в течение 24 часов после final review

Отправляется пакет из пяти частей:
1. executive brief на `1` страницу;
2. scorecard на `1` страницу;
3. proof appendix на `1-2` страницы;
4. decision memo на `1` страницу;
5. rollout note на следующие `14` дней.

Если вместо пакета уходит только "было полезно", пилот не закрыт.

## 2. Документ 1. Executive Brief

### Готовая структура

```text
Тема пилота:
Функция / команда:
Период:
Business owner:

1. Зачем запускали пилот:
- 

2. Что подтвердилось:
- 
- 
- 

3. Что появилось на выходе:
- shared scenario:
- shared template:
- shared checklist:
- proof case:

4. Какой управленческий вывод:
- scale / improve / narrow / stop

5. Что просим согласовать:
- 
```

### Правило качества

Executive brief слабый, если в нем нет:
1. одного shared scenario;
2. одного решения;
3. одного запроса к ЛПР.

### Как заполнять

2. Комментарий пишется только в одну строку.
3. Если число спорное, лучше оставить пустым, чем придумывать.

## 4. Документ 3. Proof Appendix

### Что положить внутрь

| Блок | Что приложить | Минимум |
|---|---|---|
| Before / after | `1-2` пары кейсов до / после | `2` пары |
| Shared template | рабочий шаблон команды | `1` |
| Shared checklist | checklist проверки | `1` |
| Proof case | завершенный mini-project или реальный сценарий | `1` |
| Usage proof | примеры применения общего сценария | `3` кейса |
| Qualitative proof | цитаты участников и manager note | `3 + 1` |

### Правило отбора

Не кладем в appendix:
1. выдуманные кейсы;
2. чувствительные данные без обезличивания;
3. длинные выгрузки без интерпретации;
4. артефакты, которые не подтверждают shared scenario.

## 5. Документ 4. Decision Memo

### Готовая форма

```text
Решение по пилоту:

1. Recommendation:
- scale
- improve
- narrow
- stop

2. Почему:
- 
- 
- 

3. Что масштабируем:
- 

4. Что не масштабируем:
- 

5. Какие 3 правки обязательны перед следующей волной:
- 
- 
- 

6. Что нужно от ЛПР:
- утвердить вторую волну / сузить scope / поставить на паузу
```

### Когда decision memo можно отправлять

Только если:
1. есть baseline и финал;
2. есть один общий сценарий;
3. нет незакрытого red-инцидента;
4. в memo записано, что именно не масштабируем.

## 6. Документ 5. Rollout Note на 14 дней

### Шаблон

| День | Действие | Владелец | Выход |
|---|---|---|---|
| `D1-D2` | зафиксировать решение и состав волны 2 | ЛПР + owner | утвержденный scope |
| `D3-D4` | обновить rules и red-zone exclusions | owner | policy note |
| `D5-D6` | утвердить template и checklist как team standard | manager | standard pack |
| `D7-D8` | выбрать cohort волны 2 | owner | cohort list |
| `D9-D10` | обновить baseline по новой группе | manager | baseline v2 |
| `D11-D12` | подготовить kickoff пакет | ваша сторона | kickoff pack |
| `D13-D14` | провести launch review | owner + ваша сторона | start decision |

### Обязательные поля rollout note

```text
Ответственный за волну 2:
Какая команда идет следующей:
Какой сценарий переносим без изменений:
Какие сценарии не переносим:
Какие policy rules добавляем:
Какую дату review ставим:
```

## 7. Cover note для письма ЛПР

### Готовый текст

```text
Коллеги, направляем итоговый пакет по AI-пилоту.

Внутри:
1. executive brief с главным выводом;
2. scorecard с baseline и финалом;
3. proof appendix с реальными артефактами;
4. decision memo;
5. rollout note на следующие 14 дней.

Просим подтвердить одно решение:
- масштабируем,
- дорабатываем и повторяем,
- сужаем,
- ставим на паузу.

Ключевой вывод пилота:
[вставить 2-3 строки без маркетингового языка]
```

## 8. Минимальный стандарт сильного ЛПР-пакета

Сильный пакет для ЛПР:
1. читается за `5-7` минут;
2. содержит одно решение, а не набор опций без рекомендации;
3. показывает baseline и финал рядом;
4. опирается на реальные артефакты;
5. заканчивается конкретным следующим действием и владельцем.
