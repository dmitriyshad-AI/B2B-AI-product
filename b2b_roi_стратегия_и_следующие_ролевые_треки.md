# B2B-стратегия окупаемости и следующие ролевые треки

Дата: 21 марта 2026
Статус: канонический документ по B2B-обещанию, логике окупаемости и приоритету следующих ролевых треков

## 1. Главный вывод

Продавать продукт в B2B нужно не как:

- "курс по AI для сотрудников";
- "гарантированный рост прибыли";
- "масштабное внедрение AI сразу на всю компанию".

Продавать нужно как:

`короткий управляемый пилот, который за 14-45 дней дает измеримый эффект на конкретных рабочих сценариях и управленческое решение по следующей волне.`

Это не ослабляет продажу. Это делает ее:

- честной;
- защищаемой;
- понятной финансовому директору;
- масштабируемой.

## 2. Что реально можно обещать

### Можно обещать

1. быстрый управляемый старт без хаотичного использования AI;
2. измеримые быстрые результаты на согласованных сценариях;
3. повторяемые сценарии использования, а не разовые эксперименты;
4. общий шаблон, общий чек-лист и готовый для владельца отчет;
5. решение `scale / improve / narrow / stop` по итогам пилота;
6. в части функций — наблюдаемое сокращение времени цикла, экономию трудозатрат или рост пропускной способности команды.

### Нельзя обещать как базовую формулировку

1. рост прибыли у любой компании;
2. рост выручки как прямой гарантированный результат курса;
3. одинаковый ROI для всех функций;
4. окупаемость без baseline, ответственного руководителя и одного выбранного сценария;
5. замену команды AI.

## 3. Как формулировать гарантию

Правильная гарантия в B2B:

`Мы гарантируем не абстрактный рост прибыли, а достижение согласованных результатов пилота на выбранной функции и сценарии.`

Рабочая формула гарантии:

1. до старта фиксируются:
- функция;
- ответственный руководитель;
- общий сценарий;
- baseline;
- зеленые пороги;
- срок пилота;

2. в конце пилота проверяются:
- активация;
- первая практическая победа;
- доля повторяемых сценариев;
- общие артефакты;
- записка с решением;
- одна бизнес-метрика сценария;

3. если согласованные результаты пилота не достигнуты по нашей зоне ответственности:
- даем дополнительный цикл усиления;
- или бесплатное продление;
- или скидку на следующую волну.

### Что не гарантировать даже в пилоте

Не гарантировать:

- выигранную выручку по закрытым сделкам;
- рост EBITDA;
- рост маржи по компании в целом;
- полную окупаемость без управленческой дисциплины на стороне клиента.

## 4. Как связывать обучение с P&L

Есть только четыре честных рычага связи с деньгами:

1. `Ускорение выручки`
- быстрее уходят письма по итогам встреч;
- быстрее готовятся предложения и КП;
- выше скорость перехода по воронке;
- выше производительность коммерческой команды;

2. `Снижение затрат`
- меньше ручной рутины;
- ниже cost-to-serve;
- меньше времени на первичный разбор документов, писем, встреч;

3. `Защита маржи`
- меньше ошибок;
- меньше потерь качества в черновиках;
- меньше дорогих ручных циклов согласования;

4. `Освобождение мощности команды`
- та же команда делает больше;
- быстрее запускает кампании, встречи, документы, summaries, prep work.

## 5. Какие KPI продавать по функциям

### Продажи / клиентская работа / ведение клиентов

Подходит для обещаний:

- скорость движения по воронке;
- скорость отправки письма по итогам встречи;
- скорость подготовки предложения;
- качество и полнота заметок по диагностике клиента;
- число качественных клиентских касаний на одного сотрудника.

Что можно говорить:

`Мы не обещаем вам рост выручки сам по себе. Мы обещаем ускорить коммерческий цикл и повысить качество повторяемых клиентских действий, которые влияют на выручку.`

### Маркетинг / контент / коммуникации

Подходит для обещаний:

- campaign execution speed;
- content throughput;
- testing velocity;
- speed-to-brief / speed-to-draft;
- объем гипотез и тестов на ту же команду.

Что можно говорить:

`Мы ускоряем производство и тестирование маркетинговых материалов, а не обещаем магический рост ROMI без изменений в каналах и продукте.`

### Клиентский сервис / сопровождение клиентов / сервисные операции

Подходит для обещаний:

- время обработки обращения;
- скорость решения;
- качество первого ответа;
- стоимость обслуживания;
- качество и стабильность последующих сообщений клиенту.

Что можно говорить:

`Мы помогаем снизить стоимость обслуживания и ускорить решение типовых обращений без потери проверки человеком.`

### Операции / PM / аналитики / интеллектуальная работа

Подходит для обещаний:

- cycle time;
- скорость подготовки документов;
- скорость подготовки встреч;
- скорость статусов, служебных записок, кратких выжимок и заметок для подготовки;
- скорость входа в тему и первичного анализа.

Что можно говорить:

`Мы сокращаем время на координационно тяжелую интеллектуальную работу и повышаем повторяемость рабочих сценариев.`

### HR / recruiting

Подходит для обещаний:

- скорость подготовки JD;
- скорость screening templates и interview packs;
- onboarding materials throughput;
- скорость подготовки внутренних коммуникаций.

Что можно говорить:

`Мы ускоряем HR-операционку и внутренние коммуникации, но не продаем это как главный P&L-рычаг первой волны.`

### Юристы / compliance

Подходит только для осторожных обещаний:

- скорость первого черновика;
- скорость подготовки выжимки;
- скорость первичного выявления проблем;
- стабильность заметок по проверке пунктов.

Что нельзя обещать:

- "AI для юристов быстро окупится";
- "можно безопасно автоматизировать юридическую проверку типовым записанным курсом".

Этот трек лучше делать позднее, когда:

- есть сильный B2B-бранд;
- есть юридический доменный эксперт;
- есть безопасный нормативный контур;
- есть готовность к длинному циклу продаж.

## 6. Строгий приоритет следующих треков

### Не следующий трек: руководители

Руководители не должны быть следующим самостоятельным большим продуктом.

Правильная роль manager layer:

- обязательная надстройка над B2B-пилотом;
- усилитель внедрения;
- слой, который облегчает покупку для владельца пилота и руководителя функции.

Вывод:

`слой руководителя нужно усиливать как надстройку, но не тратить следующую основную продуктовую итерацию на отдельный большой курс для руководителей.`

### Трек №1: продажи и работа с клиентами

Это следующий лучший трек после Core и трека по операциям и интеллектуальной работе.

Почему:

1. самая понятная для ЛПР связь с деньгами;
2. много повторяемых текстовых и коммуникативных сценариев;
3. легко показать before/after;
4. легко посчитать speed metrics;
5. коммерческие руководители готовы покупать то, что ускоряет воронку и follow-up.

Что должно войти:

1. discovery prep;
2. meeting notes -> next-step follow-up;
3. account plan drafts;
4. objection handling prep;
5. proposal / КП first draft;
6. CRM note hygiene and summary;
7. pipeline review memo.

### Трек №2: Marketing / Content / Communications

Это лучший следующий трек для broad-market распространения.

Почему:

1. почти у каждой компании есть marketing-like функция;
2. очень много повторяемых сценариев;
3. быстро виден output;
4. легко делать recorded format;
5. можно продавать и B2B, и B2C.

Но:

1. рынок перегрет;
2. у многих маркетологов уже есть базовый self-serve опыт;
3. нельзя выходить с общим тезисом "AI для маркетологов".

Нужен более узкий трек:

- briefing;
- messaging draft;
- campaign asset repurposing;
- research and competitor scan;
- content QA;
- test hypothesis generation.

### Трек №3: Customer Support / Customer Success / Service Ops

Это очень сильный ROI-трек, особенно для SaaS, сервисных и платформенных компаний.

Почему:

1. высокая повторяемость;
2. много текстовых сценариев;
3. легко считать скорость и качество;
4. легко собрать общий шаблонs;
5. у less-experienced сотрудников эффект часто заметнее.

Когда поднимать его выше маркетинга:

- если целевой рынок — SaaS, e-commerce, техподдержка, сервисные компании, EdTech, FinTech;
- если buyer уже думает категориями `cost-to-serve` и SLA.

## 7. Категории, которые руководство реально охотнее покупает

### Самые покупаемые в первой волне

1. продажи и клиентские команды;
2. marketing / content / communications;
3. customer support / customer success / service ops;
4. operations / PM / analyst-heavy teams.

### Покупаемые, но как вторая волна

1. HR / recruiting;
2. finance / FP&A / reporting teams;
3. product / strategy / research teams.

### На потом

1. legal;
2. compliance;
3. procurement-heavy функции;
4. узкоспециализированные regulated teams.

## 8. Что это значит для текущего проекта

Сейчас у вас уже есть:

1. `Core`;
2. `operations / knowledge work`;
3. `manager layer lite`;
4. `company layer`.

Значит, самое правильное развитие линейки:

1. не расширять manager layer в отдельную большую академию;
2. не идти следующим шагом в legal;
3. следующим крупным ролевым треком делать `Продажи и работа с клиентами`;
4. после него делать `Marketing / Content / Communications`;
5. затем — `Customer Support / Customer Success`, если хотите усиливать ROI-story для service-heavy B2B.

## 9. Рабочая продуктовая лестница

### Для первой B2B-продажи

Продается:

- `Core + manager layer + company layer + один безопасный для пилота scenario`.

### Для второй продажи в ту же компанию

Продается:

- `Core + один функциональный трек + manager wrapper`.

### Для масштабирования

Продается:

- `Core + 2-3 role tracks + company layer + rollout support`.

## 10. Финальный вывод

Если цель — сделать один из самых сильных и продаваемых B2B-продуктов по AI для российских компаний, то продукт надо строить не по логике "кому еще можно что-то рассказать", а по логике:

1. где проще доказать measurable effect;
2. где проще показать repeatable workflow;
3. где buyer видит связь с выручкой, cost-to-serve, cycle time или маржой;
4. где recorded training реально может стать частью pilot system, а не только вдохновляющим контентом.

Строгий приоритет сейчас:

1. `Sales / Client Work`
2. `Marketing / Content / Communications`
3. `Customer Support / Customer Success`

слой руководителя — не следующий трек, а обязательный multiplier.
Legal — не сейчас.
