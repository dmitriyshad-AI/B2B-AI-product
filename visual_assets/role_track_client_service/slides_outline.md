# Покадровая структура визуальных материалов

## C1. Разбор и приоритизация обращения

1. Титульный экран — не каждое обращение требует одинаковой реакции.
2. Главный экран — карта triage: что случилось, срочность, кого затронуло, ожидание клиента, владелец, следующий шаг.
3. Финальный экран — разобрать одно живое обращение по карте triage.

## C2. Выжимка контекста

1. Титульный экран — без контекста хороший ответ не получится.
2. Главный экран — выжимка по тикету: кто клиент, история, что обещали, риск, что важно сейчас.
3. Финальный экран — собрать одну краткую выжимку перед ответом.

## C3. Первый ответ

1. Титульный экран — первый ответ должен снижать напряжение, а не создавать новые вопросы.
2. Главный экран — структура первого ответа: подтверждаем, объясняем, следующий шаг, ожидание.
3. Финальный экран — переписать один реальный ответ по новой структуре.

## C4. Эскалация

1. Титульный экран — плохая эскалация сжигает время двух команд сразу.
2. Главный экран — бриф эскалации: симптом, контекст, что проверили, что нужно, риск.
3. Финальный экран — оформить одну эскалацию по стандарту.

## C5. Контакт по зависшему вопросу

1. Титульный экран — молчание клиента раздражает сильнее, чем честная неопределенность.
2. Главный экран — структура follow-up: статус, что сделали, что ждем, когда вернемся, что важно клиенту.
3. Финальный экран — собрать follow-up по зависшему вопросу.

## C6. Еженедельный обзор по сервису

1. Титульный экран — сервисный обзор нужен для решений, а не для ощущения пожара.
2. Главный экран — таблица: что повторяется, где bottleneck, где риск SLA, что разбираем на неделе.
3. Финальный экран — собрать weekly review по сервисным сигналам.
