# Slides Outline

Пакет покрывает визуальные экраны для production-ритма каждого модуля:
1. `A-roll hook`
2. `Title card`
3. `One-screen framework`
4. `Screen demo`
5. `A-roll close / final card`

## R1. Разложить запуск в управляемую структуру

1. `Hook`
   Боль: есть формулировка "нужно быстро запустить внутренний пилот на 2 недели", но еще нет проекта.
2. `Title card`
   Asset: `r1_title_card.svg`
   Задача экрана: назвать модуль и собрать формулу `Outcome -> Constraints -> Workstreams -> Owners -> Checkpoints -> Risks`.
3. `Framework screen`
   Asset: `r1_launch_breakdown_screen.svg`
   Задача экрана: показать переход от сырого входа к `task breakdown canvas`.
4. `Screen demo`
   Asset: `r1_launch_breakdown_screen.svg`
   Задача экрана: проговорить обязательные элементы запуска, owner, checkpoint и риск перегруза.
5. `Final card`
   Asset: `r1_final_card.svg`
   Задача экрана: зафиксировать принцип "без owner и checkpoint задача остается пожеланием" и выдать homework.

## R2. Делать статус-апдейты и рабочие документы без шума

1. `Hook`
   Боль: weekly update превращается в длинный пересказ, который руководитель не читает.
2. `Title card`
   Asset: `r2_title_card.svg`
   Задача экрана: открыть модуль и вывести формулу `Progress -> Risks -> Slippage -> Next steps -> Attention needed`.
3. `Before/after screen`
   Asset: `r2_status_update_before_after.svg`
   Задача экрана: визуально столкнуть длинный хаотичный текст и `signal-first update`.
4. `Screen demo`
   Asset: `r2_status_update_before_after.svg`
   Задача экрана: разобрать 4 направления работ, 2 риска, 1 сдвиг срока и 3 next steps в коротком формате.
5. `Final card`
   Asset: `r2_final_card.svg`
   Задача экрана: закрепить, что хороший update нужен для следующего управленческого шага, а не для солидного тона.

## R3. Готовиться к встречам и фиксировать follow-up

1. `Hook`
   Боль: встреча проходит, но после нее не остается ни решений, ни owners.
2. `Title card`
   Asset: `r3_title_card.svg`
   Задача экрана: назвать модуль и показать формулу `Context -> Tensions -> Questions -> Decisions -> Owners -> Deadlines`.
3. `Framework screen`
   Asset: `r3_meeting_prep_followup_screen.svg`
   Задача экрана: разложить логику `prep note` до встречи и `follow-up` после встречи.
4. `Screen demo`
   Asset: `r3_meeting_prep_followup_screen.svg`
   Задача экрана: провести зрителя через проблемный созвон, список вопросов, решения и unresolved issues.
5. `Final card`
   Asset: `r3_final_card.svg`
   Задача экрана: зафиксировать, что хорошая встреча заканчивается управленческим движением в тот же день.

## R4. Сравнивать варианты и риски без самообмана

1. `Hook`
   Боль: модель легко выдает "лучший вариант", если не задать критерии и trade-offs.
2. `Title card`
   Asset: `r4_title_card.svg`
   Задача экрана: открыть модуль и собрать формулу `Option -> Benefit -> Cost -> Risk -> Mitigation -> Fit`.
3. `Framework screen`
   Asset: `r4_options_risk_matrix.svg`
   Задача экрана: показать `options and risk memo` в виде одностраничной матрицы.
4. `Screen demo`
   Asset: `r4_options_risk_matrix.svg`
   Задача экрана: сравнить три способа сократить время адаптации новых сотрудников без автоматического выбора победителя.
5. `Final card`
   Asset: `r4_final_card.svg`
   Задача экрана: закрепить, что главный результат здесь — карта мышления, а не решение за человека.

## R5. Собрать личный операционный AI-pipeline

1. `Hook`
   Боль: AI пробовали везде, но ничего не повторяется и не превращается в систему.
2. `Title card`
   Asset: `r5_title_card.svg`
   Задача экрана: назвать модуль и показать формулу `Input -> Prompt pattern -> Quality gate -> Output -> Storage -> Reuse`.
3. `Framework screen`
   Asset: `r5_personal_ops_pipeline.svg`
   Задача экрана: вывести одну таблицу личного пайплайна на 3 повторяющихся процесса.
4. `Screen demo`
   Asset: `r5_personal_ops_pipeline.svg`
   Задача экрана: разобрать процессы `встречи`, `статус-апдейты`, `summary` и их quality gates.
5. `Final card`
   Asset: `r5_final_card.svg`
   Задача экрана: закрыть трек мостом от личной дисциплины к будущей team library.
