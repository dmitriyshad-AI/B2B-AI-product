# Система оценки базового модуля

Дата: 21 марта 2026
Статус: канонический framework для оценки и отчетности

## 1. Зачем нужен этот документ

Этот документ фиксирует:
- как измеряется прогресс ученика;
- что считается прохождением базовый модуль;
- как связаны результаты обучения, задания и итоговый мини-проект;
- как использовать базовый модуль в корпоративной диагностике.

## 2. Что измеряем

В базовый модуль измеряются не абстрактные знания, а 5 способностей:

1. Умение выбирать уместные задачи для AI.
2. Умение ставить задачу AI с контекстом и критериями.
3. Умение проверять и дорабатывать результат.
4. Умение использовать AI безопасно и осознанно.
5. Умение встроить AI в повторяющиеся рабочие сценарии.

## 2.1. Единая шкала оценки

Для всех ключевых способностей используется простая 4-уровневая шкала:

0. Не проявлено:
- участник не демонстрирует навык даже с подсказками.

1. Базово:
- участник понимает принцип, но применяет его неполно или нестабильно.

2. Рабочий уровень:
- участник применяет навык на реальной задаче и получает пригодный результат.

3. Повторяемый уровень:
- участник показывает, что навык можно использовать повторно и встроить в работу или командный стандарт.

## 3. Входная диагностика

До старта ученик должен заполнить:

1. Самооценку:
- насколько часто он уже использует AI;
- где он чувствует уверенность;
- где чувствует барьеры;
- чего опасается;
- какие задачи хочет ускорить.

2. Baseline-оценку:
- одну простую рабочую задачу он описывает привычным способом;
- фиксирует, сколько времени она обычно занимает;
- оценивает качество текущего результата.

## 4. Диагностика в процессе

Основные точки:
- домашняя работа 1: выбраны реальные задачи;
- домашняя работа 2: собраны рабочие шаблоны;
- домашняя работа 3: проверка и доработка результата;
- домашняя работа 4: библиотека сценариев;
- домашняя работа 5: план внедрения;
- мини-проект: полный цикл применения.

Постановка мини-проекта берется из:
- [мини_проект_базового_модуля.md](/Users/dmitrijfabarisov/Projects/Dmitriy+Arseniy AI corp course/мини_проект_базового_модуля.md)

## 4.1. Стандарт быстрой ручной проверки

Проверяющий должен видеть первым экраном:
1. Какую реальную задачу решал участник.
2. Какой запрос или сценарий он применил.
3. Как он проверил результат.
4. Что получилось на выходе.
5. Почему это можно считать рабочим или повторяемым.

Если этого нельзя понять за 1-2 минуты, сдача считается слишком размытой для массовой проверки.

## 5. Выходная диагностика

В конце модуля ученик:
- оценивает, какие задачи начал решать быстрее;
- показывает 3-5 сценариев, которые реально будет использовать;
- сдает итоговый мини-проект;
- повторно отвечает на вопросы самооценки.

## 6. Матрица связи outcomes и assessment

| Outcome | Где проверяется |
|---------|-----------------|
| Выбирает подходящие задачи для AI | Домашняя 1, стартовый блок, мини-проект |
| Формулирует сильные запросы | Домашняя 2, уроки 5-10, мини-проект |
| Проверяет и дорабатывает результат | Домашняя 3, уроки 11-15, мини-проект |
| Собирает рабочие сценарии | Домашняя 4, уроки 16-21 |
| Встраивает AI в свою систему | Домашняя 5, уроки 22-24, мини-проект |

## 7. Итоговая логика зачета

базовый модуль считается пройденным, если:
1. Ученик выполнил обязательные домашние задания.
2. Ученик сдал итоговый мини-проект.
3. По мини-проекту видно, что AI использован осмысленно.
4. Есть признаки, что сценарий можно реально повторить в работе.
5. Ученик понимает риски и ограничения.

Минимальный зачетный стандарт:
- по каждой из 5 способностей участник должен быть не ниже уровня `1`;
- минимум по 3 из 5 способностей участник должен дойти до уровня `2`;
- минимум по 1 способности должен появиться уровень `3` или явный артефакт результата повторяемости.

## 7.1. Что считать сильным финальным мини-проектом

Проверяющий должен увидеть:
1. реальный сценарий;
2. baseline или слабый старт;
3. осмысленный prompt / workflow;
4. проверку результата;
5. ручную доработку;
6. финальный рабочий артефакт;
7. правило повторного применения.

Если в проекте нет хотя бы 5 из этих 7 элементов, проект не должен считаться сильным.

## 8. Корпоративное использование assessment framework

В корпоративной версии этот framework позволяет:
- измерить стартовый уровень участников;
- увидеть, какие сценарии у них появились;
- показать руководителю, что именно освоили сотрудники;
- использовать мини-проекты как первичную библиотеку внутренних кейсов.

### Что должно попасть в короткий B2B-отчет

1. Сколько людей активировались после сессии 0.
2. Сколько людей дошли до 1+ артефакт результата.
3. Какие способности выросли заметнее всего.
4. Какие 1-3 сценария оказались наиболее жизнеспособными.
5. Где остаются риски и что надо доработать перед следующей волной.

### Канонические B2B-выходы

Для корпоративной версии обязательны 4 готовых выхода:
1. manager summary;
2. group report;
3. team input/output compare;
4. decision block для owner.
