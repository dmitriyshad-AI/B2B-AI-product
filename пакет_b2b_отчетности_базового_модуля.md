# Базовый модуль B2B Reporting Pack

Дата: 21 марта 2026
Статус: канонический пакет отчетности для B2B-пилота и корпоративного запуска

## 1. Зачем нужен этот пакет

Этот пакет нужен, чтобы базовый модуль в корпоративной версии давал не только обучение, но и понятный управленческий выход.

После B2B-пилота у owner и ЛПР должны остаться:
- короткий manager summary;
- group report по группе;
- input/output compare по команде;
- решение, что делать дальше.

## 2. Manager summary на 1 экран

### Шаблон

```text
базовый модуль: manager summary

Пилот:
Группа:
Период:

1. Активация:
- сколько участников вошли в курс
- сколько сделали первая практическая победа

2. Практические результаты:
- сколько участников сдали минимум 1 рабочий артефакт
- какие 3 сценария оказались самыми жизнеспособными

3. Качество применения:
- где команда уже на рабочем уровне
- где остается желтая или красная зона

4. Что делать дальше:
- закрепить
- доработать
- не масштабировать без дополнительных правил
```

### Заполненный пример

```text
базовый модуль: manager summary

Пилот: AI Basics Pilot
Группа: 24 сотрудника операционного и клиентского блока
Период: 2 недели

1. Активация:
- 22 из 24 вошли в курс
- 19 из 24 сделали первая практическая победа

2. Практические результаты:
- 16 из 24 собрали минимум 1 рабочий артефакт
- самые жизнеспособные сценарии:
  1. follow-up после встреч
  2. summary длинных заметок и документов
  3. подготовка к статус-созвонам

3. Качество применения:
- на рабочем уровне: структурирование запроса, summary, follow-up
- зона внимания: внешние обещания клиентам, работа с чувствительными данными, риск ложной уверенности

4. Что делать дальше:
- закрепить 3 сценария как team standard
- ввести короткий checklist для yellow-zone задач
- не расширять использование на внешние обещания и юридические тексты без отдельного policy gate
```

## 6. Decision block для owner

### Шаблон решения

```text
Решение по итогам пилота:

1. Что масштабируем на всю команду:
2. Что оставляем только как личный сценарий:
3. Где нужен manager control:
4. Какие 1-2 policy rules вводим до следующей волны:
5. Нужен ли role-based track после Core:
```

### Заполненный пример

```text
Решение по итогам пилота:

1. Масштабируем:
- follow-up после встреч
- summary длинных заметок
- prep к статус-созвонам

2. Оставляем как личные сценарии:
- быстрый вход в новую тему
- внутренние черновики структур и записок

3. Нужен manager control:
- внешние письма клиентам
- тексты с обещанием сроков, цены, scope

4. Вводим 2 policy rules:
- нельзя копировать AI-текст во внешнюю коммуникацию без ручной проверки
- нельзя загружать чувствительные данные без отдельного правила и одобрения

5. После Core нужен role-based track:
- для customer-facing команд
- для project / operations команд
```

## 7. Короткий вывод

Если после пилота у компании нет этих 4 выходов:
- manager summary;
- group report;
- input/output compare;
- decision block;

значит обучение еще не доведено до корпоративного стандарта.
