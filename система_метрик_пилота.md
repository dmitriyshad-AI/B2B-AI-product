# Pilot Metrics Framework

Дата: 21 марта 2026
Статус: максимально прикладной framework метрик и порогов решений

## 1. Главный принцип

После пилота нельзя оставаться с общим ощущением "вроде было полезно".

Нужны 3 линии решения:
1. `activation`
2. `repeatable use`
3. `артефакт результатаs`

## 2. Основные метрики

| Метрика | Как считать | Green | Yellow | Red |
|---|---|---|---|---|
| Start rate | стартовали / зарегистрировались | >= 80% | 60-79% | < 60% |
| Session 0 completion | прошли сессию 0 / стартовали | >= 75% | 55-74% | < 55% |
| Первая практическая победа rate | зафиксировали первая практическая победа / стартовали | >= 65% | 45-64% | < 45% |
| Reach lesson 5 | дошли до урока 5 / стартовали | >= 60% | 40-59% | < 40% |
| Homework completion | сдали ключевые домашние / стартовали | >= 50% | 30-49% | < 30% |
| Mini-project completion | сдали mini-project / стартовали | >= 45% | 25-44% | < 25% |
| Repeatable scenario rate | есть 1+ repeatable scenario / стартовали | >= 50% | 30-49% | < 30% |
| Template retention rate | сохранили 1+ рабочий шаблон / стартовали | >= 50% | 30-49% | < 30% |
| 14-day plan rate | собрали план внедрения / стартовали | >= 50% | 30-49% | < 30% |

## 3. B2B-метрики

| Метрика | Как считать | Green | Yellow | Red |
|---|---|---|---|---|
| Shared scenario | есть / нет | есть | частично | нет |
| Shared template | есть / нет | есть | сырой | нет |
| Shared checklist | есть / нет | есть | сырой | нет |
| Owner confidence | готов масштабировать / доработать / остановить | масштабировать | доработать | остановить |
| Proof for management | есть короткий report без натяжки | есть | слабый | нет |

## 4. Качественные сигналы

### Сильные сигналы

1. Люди описывают пользу языком работы.
2. Люди называют конкретные сценарии, а не "стало интереснее".
3. Участники сами хотят сохранить шаблоны.
4. Руководитель видит общий сценарий, а не хаос.

### Слабые сигналы

1. Нравится тема, но нет внедрения.
2. Есть просмотр, но нет действий.
3. Есть интерес, но нет reusable artifacts.
4. Отчеты получаются слишком общими.

## 5. Минимальный размер доказательств

Пилот нельзя считать сильным, если на выходе нет:
1. минимум `5` сильных первая практическая победаs в B2C beta или `3` в B2B pilot;
2. минимум `5` пригодных шаблонов или `1 общий шаблон` для B2B;
3. минимум `3` мини-проекта, которые можно показать без стыда;
4. минимум `3` цитат языком работы;
5. минимум `1` управленческого вывода по следующему шагу.

## 6. Decision logic

### Scale

Идем в scale, если одновременно:
1. session 0 completion `>= 75%`;
2. первая практическая победа rate `>= 65%`;
3. repeatable scenario rate `>= 50%`;
4. mini-project completion `>= 45%`;
5. есть артефакт результатаs;
6. для B2B есть общий сценарий и готовый для владельца report.

### Improve Then Repeat

Идем в improve, если:
1. early value есть, но completion проседает;
2. homework и LMS-path создают лишнее трение;
3. артефакт результатаs есть, но их мало или они слабоваты;
4. owner в B2B видит потенциал, но не готов масштабировать без правок.

### No-Go

Идем в no-go, если:
1. start rate низкий;
2. early value не появляется;
3. repeatable use почти нет;
4. участники не доходят до артефактов;
5. невозможно показать правдоподобный report.

## 7. Что считать главным числом пилота

Если нужно одно число для короткого обсуждения, используйте:

`Pilot readiness index = среднее по 4 метрикам`
- session 0 completion
- первая практическая победа rate
- repeatable scenario rate
- mini-project completion

Интерпретация:
- `>= 60%` — сильный сигнал
- `45-59%` — продукт живой, но требует tightening
- `< 45%` — пилот еще слаб для масштабирования
