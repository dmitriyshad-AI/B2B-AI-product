# Корпоративный слой

Дата: 22 марта 2026
Статус: concrete-first operating pack для owner, функционального руководителя и корпоративного rollout

## 1. Что компания должна покупать на первой волне

Первая волна продается не как "обучение по AI", а как управляемый pilot system с конкретным выходом.

Минимальный corporate-ready output:
1. одна пилотная группа;
2. один business owner;
3. один shared scenario;
4. один shared template;
5. один shared checklist;
6. один final scorecard;
7. один decision memo;
8. один rollout plan на следующие `14` дней.

Если любой из этих восьми элементов отсутствует, корпоративный слой не собран.

## 2. Launch gate для компании

До старта должны быть закрыты все условия:

| Gate | Что должно быть подтверждено | Кто подтверждает | Стоп-фактор |
|---|---|---|---|
| `G1` | есть business owner | клиент | owner не назначен |
| `G2` | выбрана одна функция или одна команда | клиент | хотят пилот на всю компанию |
| `G3` | выбран один shared scenario | клиент + ваша сторона | список кейсов без приоритета |
| `G4` | определен baseline period | клиент | нет данных для сравнения |
| `G5` | согласованы green / yellow / red зоны | клиент + ваша сторона | спор по безопасности |
| `G6` | список участников финализирован | клиент | группа плавающая |
| `G7` | утверждены kickoff, midpoint, final review | клиент | нет календаря review |
| `G8` | согласовано, какие proof artifacts собираем | обе стороны | пилот без доказательств |
| `G9` | согласован формат финального решения | owner / ЛПР | хотят "посмотрим потом" |

### Таблица baseline по сценарию

| Блок | Поле | Как считаем | База | Источник | Комментарий |
|---|---|---|---:|---|---|
| Объем | Cases per week | число кейсов по shared scenario за неделю |  | CRM / задачи / ticketing | только одна функция |
| Скорость | Cycle time | минуты от входа до первого пригодного результата |  | CRM / self-report / sample | берем медиану или среднее |
| Качество | First-pass quality | `кейсы без существенной правки / все кейсы` |  | ручная выборка `15-20` кейсов | фиксируем критерий качества заранее |
| Доработка | Rework rate | `кейсы с возвратом на переработку / все кейсы` |  | выборка кейсов | важно для ROI |
| Применение | Existing adoption | `люди, уже применяющие AI на этом сценарии / группа` |  | опрос + sample | baseline по хаосу |
| Риск | Safety incidents | число фактических нарушений или near misses |  | ручной лог | `0` — тоже значение |
| Экономика | Loaded hour cost | стоимость часа роли с налогами и overhead |  | finance / HR / estimate | нужна для ROI |
| Управление | Decision deadline | дата, к которой owner должен принять решение |  | календарь | без дедлайна пилот размывается |

## 4. Corporate Scorecard

| Линия | Метрика | Green | Yellow | Red | Факт | Статус | Владелец |
|---|---|---|---|---|---:|---|---|
| Активация | Start rate | `>= 85%` | `70-84%` | `< 70%` |  |  | owner |
| Активация | Session 0 completion | `>= 75%` | `55-74%` | `< 55%` |  |  | owner |
| Early value | First win rate | `>= 65%` | `45-64%` | `< 45%` |  |  | manager |
| Повторяемость | Shared scenario usage | `>= 60%` | `40-59%` | `< 40%` |  |  | manager |
| Повторяемость | Shared template adoption | `>= 70%` | `50-69%` | `< 50%` |  |  | manager |
| Качество | First-pass quality | `>= 80%` | `65-79%` | `< 65%` |  |  | manager |
| Скорость | Cycle time delta | `-20% и лучше` | `-10% ... -19%` | `хуже -10%` |  |  | owner |
| Риск | Safety incidents | `0` | `1 исправленный` | `2+` |  |  | owner |
| Доказательства | Shared checklist | есть и используется | есть, но сырой | нет |  |  | manager |
| Экономика | Weekly value signal | положительный и подтвержденный | положительный, но сырой | нет сигнала |  |  | owner |

### Правила интерпретации

- `scale`: нет red по рискам, есть общий сценарий, шаблон, чек-лист и положительный экономический сигнал.
- `improve`: сильный shared scenario есть, но template adoption, quality или cycle time пока в yellow.
- `narrow`: один сценарий сильный, остальная функция не готова.
- `stop`: нет owner, нет signal of use, нет shared artifacts или есть red по безопасности.

## 5. Роли и operating rhythm

| Роль | До старта | Во время пилота | На финале |
|---|---|---|---|
| Business owner | подтверждает задачу и decision gate | снимает блокеры и участвует в midpoint | принимает решение scale / improve / narrow / stop |
| Functional manager | утверждает сценарий и baseline | следит за template, checklist и quality | подтверждает рабочий сценарий |
| Participants | получают правила и onboarding | выполняют кейсы и mini-projects | закрепляют повторяемый сценарий |
| Ваша сторона | настраивает контур, шаблоны и метрики | собирает артефакты и отчетность | отдает final pack и recommendation |

Ритм фиксируется заранее:
1. kickoff;
2. midpoint-check;
3. final review;
4. follow-up письмо с next-step pack в течение `24 часов`.

## 7. Wave 2 gate

Во вторую волну идем только если одновременно:
1. owner подтвержден и готов тратить время на governance;
2. shared scenario доказан на одной группе;
3. есть template и checklist, которыми реально пользуются;
4. нет red incidents;
5. есть экономический сигнал, который можно показать ЛПР без натяжки.

Если хотя бы один пункт не выполнен, честное решение:
- `improve`
или
- `narrow`, но не "масштабировать авансом".

## 8. Что не входит в первую версию

1. enterprise governance контур на всю компанию;
2. кастомные интеграции;
3. procurement / security review поставщика;
4. DLP-архитектура;
5. rollout сразу на несколько функций;
6. юридическая экспертиза чувствительных сценариев.

## 9. Когда корпоративный слой можно считать сильным

Корпоративный слой сильный, если:
1. owner понимает, что покупает на выходе;
2. ЛПР получает пакет, который можно переслать без устной расшифровки;
3. decision memo опирается на факты, а не на enthusiasm;
4. wave 2 запускается по gate, а не по настроению.
