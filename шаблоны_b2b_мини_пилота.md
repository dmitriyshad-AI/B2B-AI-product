# B2B Mini-Pilot Templates

Дата: 21 марта 2026
Статус: максимально прикладной набор готовых одностраничникs для корпоративного пилота

## 1. Как использовать этот файл

Это не skeleton и не список пожеланий.

Это набор готовых шаблонов, которые можно:
- копировать в Google Docs или Notion;
- пересылать owner со стороны компании;
- использовать как основу для kickoff, midpoint-check и final review.

Минимальный набор для одного B2B mini-pilot:
1. team rules;
2. use-case map;
3. pilot plan;
4. midpoint scorecard;
5. final recommendation memo.

## 2. Шаблон 1. Team Rules One-Pager

Название документа:
`Правила пилотной группы по использованию AI`

### Готовый текст

Цель этого документа:
дать группе понятные рамки до старта пилота и не допустить хаотичного использования AI.

Что разрешено:
1. черновики писем и внутренних сообщений без чувствительных данных;
2. summary обезличенных документов и заметок;
3. подготовка структуры, вопросов, планов и follow-up;
4. генерация вариантов формулировок и идей;
5. первичное исследование темы как черновой этап.

Что разрешено только после human review:
1. любые клиентские формулировки;
2. внутренние summary по рабочим данным;
3. документы, влияющие на решения руководителя;
4. тексты, где важны точность цифр, обещаний и сроков.

Что запрещено:
1. загружать персональные данные без разрешения;
2. вставлять в AI конфиденциальные договоры и финансовые документы;
3. копировать AI-output в финальный результат без ручной проверки;
4. использовать AI как единственный источник фактов.

Как работаем:
1. сначала делаем черновик;
2. потом проверяем факты, тон, риски и применимость;
3. только после этого отправляем результат дальше.

## 3. Шаблон 2. Use-Case Map

Название документа:
`Карта pilot-ready сценарии использования по команде`

### Таблица

| Use case | Для какой роли | Частота | Выход результата | Польза | Риск | Human review | Решение |
|---|---|---|---|---|---|---|---|
| Follow-up после встречи | account manager | 3-5 раз в неделю | письмо или сообщение | быстро фиксирует next step | низкий | обязателен | в пилот |
| Summary заметок звонка | team lead | 2-3 раза в неделю | short summary + actions | экономит время на фиксации | средний | обязателен | в пилот |
| Подготовка к встрече | ops / sales | 2-4 раза в неделю | prep note | улучшает качество входа в встречу | низкий | обязателен | в пилот |
| Ответ клиенту с обещанием сроков | client success | 1-2 раза в неделю | клиентское письмо | высокая ценность, но риск ошибки | высокий | обязателен | позже |
| Финансовый вывод по отчету | руководитель | 1 раз в неделю | решение | высокий риск неверной интерпретации | высокий | обязателен | не в пилот |

### Правило отбора

В первый B2B mini-pilot идут только сценарии, которые одновременно:
1. повторяются хотя бы раз в неделю;
2. имеют понятный выход;
3. не требуют доступа к закрытым данным;
4. позволяют увидеть пользу за 14 дней;
5. не ломают бизнес, если первый черновик окажется слабым.

### Что нужно утвердить owner

1. `3-5` candidate scenarios.
2. `1` общий сценарий, который станет общим фокусом пилота.
3. Какие сценарии сознательно не берем в пилот.

## 4. Шаблон 3. Pilot Plan One-Pager

Название документа:
`План B2B mini-pilot на 14 дней`

### Готовая структура

Команда:
`[название команды / функции]`

Owner со стороны компании:
`[имя, роль]`

Размер группы:
`[8-20 участников]`

Shared scenario:
`[один общий сценарий]`

Shared template:
`[какой шаблон группа должна собрать]`

Shared checklist:
`[какой checklist группа должна закрепить]`

Период пилота:
`[дата старта - дата финального review]`

Midpoint-check:
`[дата и время]`

Final review:
`[дата и время]`

Что должны собрать участники:
1. первая практическая победа;
2. минимум один repeatable scenario;
3. один рабочий template;
4. один mini-project или сильный прикладной артефакт.

Что должен получить owner:
1. short metrics snapshot;
2. общий сценарий;
3. общий шаблон;
4. общий чек-лист;
5. final recommendation: `scale / improve / narrow / stop`.

## 5. Шаблон 4. Midpoint-Check Scorecard

Название документа:
`Midpoint-check по B2B mini-pilot`

### Быстрая оценка

| Метрика | Текущее значение | Цвет | Комментарий |
|---|---|---|---|
| Session 0 completion |   | green / yellow / red |   |
| Первая практическая победа rate |   | green / yellow / red |   |
| Reach lesson 5 |   | green / yellow / red |   |
| Repeatable scenario signals |   | green / yellow / red |   |
| Shared scenario clarity |   | green / yellow / red |   |

### Вопросы на midpoint-check

1. У команды появился один общий сценарий или все еще хаос?
2. Люди описывают пользу языком работы или языком общего интереса?
3. Есть ли один шаблон, который уже можно сохранить?
4. Что мешает второй половине пилота: контент, LMS, время, мотивация или fit?
5. Нужно ли сужать scope до финального review?

### Быстрое решение после midpoint

- `continue as is`
- `continue with narrowed scope`
- `continue with extra owner push`
- `stop external commitments and convert to internal QA`

`Решение по итогам B2B mini-pilot`

`[название / команда / период]`

1.

Какие артефакты действительно появились:
1. общий сценарий:
2. общий шаблон:
3. общий чек-лист:
4. manager summary:

Решение:
- `scale`
- `improve`
- `narrow`
- `stop`

Обоснование в 5 строках:
1. activation:
2. early value:
3. repeatable use:
4. артефакт результатаs:
5. owner readiness:

Следующий шаг:
- если `scale`: какая группа идет второй волной;
- если `improve`: какие 3 правки обязательны;
- если `narrow`: какой сценарий использования становится клином;
- если `stop`: что не готово и почему.
