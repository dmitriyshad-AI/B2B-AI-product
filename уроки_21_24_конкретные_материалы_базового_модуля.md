## 2. Урок 21: L21-CASE-A. AI как инструмент самообучения

### Рабочая ситуация

Человек готовится к встрече и понимает, что плохо различает:
- когортный анализ;
- обычную помесячную сводку.

Задача:
- быстро разобраться;
- проверить, что понимание стало рабочим;
- не спутать режим объяснения с режим проверки фактов.

### Prompt chain

#### Prompt 1. Объяснить простыми словами

```text
Объясни простыми словами, что такое когортный анализ.

Контекст:
- я project manager;
- не математик;
- мне нужно понять это перед рабочей встречей;
- не используй академический язык;
- дай объяснение на 5-6 коротких пунктов.
```

#### Prompt 2. Сравнить с похожим понятием

```text
Теперь сравни когортный анализ с обычной помесячной статистикой.

Сделай таблицу из 4 строк:
- что сравниваем;
- что видно;
- где ошибка новичка;
- когда какой подход полезнее.
```

#### Prompt 3. Проверка понимания

```text
Задай мне 5 коротких вопросов по теме так, чтобы проверить, действительно ли я понял разницу.
После моих ответов скажи:
- что я понял правильно;
- что понял неполно;
- что мне стоит перепроверить отдельно.
```

#### Prompt 4. Список на внешнюю проверку

```text
Назови 3 вещи по этой теме, которые я не должен принимать на веру и должен проверить отдельно по надежным источникам.
```

### Типовой полезный output

```text
Когортный анализ — это способ смотреть не на всех пользователей сразу, а на группы людей, которые начали в один и тот же период.

Например:
- все, кто зарегистрировался в январе;
- все, кто зарегистрировался в феврале.

Потом мы смотрим, как каждая такая группа ведет себя дальше:
- вернулась ли через месяц;
- купила ли повторно;
- насколько быстро перестала пользоваться продуктом.

Это полезно, когда нужно понять не просто общий объем, а качество удержания по разным волнам пользователей.
```

### Таблица сравнения

| Вопрос | Когортный анализ | Обычная помесячная статистика |
|---|---|---|
| Что показывает | поведение одной группы во времени | общее состояние за месяц |
| Где полезен | удержание, повторные действия, качество набора | общий объем, динамика периода |
| Ошибка новичка | думать, что это просто еще одна сводка по месяцам | делать вывод о качестве удержания без разбивки по группам |
| Когда брать | когда важно понять, что происходит с конкретной волной пользователей | когда нужна общая картина периода |

### Вопросы для самопроверки

1. Что такое когорта в самом простом смысле?
2. Почему общий рост пользователей не равен хорошему удержанию?
3. Когда когортный анализ полезнее обычной сводки?
4. Какую типичную ошибку можно сделать без когортного подхода?
5. Как бы вы объяснили разницу между этими подходами коллеге в двух фразах?

### Пример ответа ученика

```text
Когорта — это группа пользователей, которые пришли в одно время.
Когортный анализ показывает, как они ведут себя дальше.
Обычная сводка по месяцу показывает общие числа, но не показывает качество удержания конкретной группы.
```

### Типовой feedback от AI

```text
Вы правильно уловили главное:
- когорта — это группа пользователей с общим стартом;
- когортный анализ показывает поведение этой группы во времени;
- обычная сводка не раскрывает качество удержания.

Что стоит уточнить:
- когортный анализ полезен не только для удержания, но и для повторных покупок, возвратов и активации;
- важно не путать рост общего числа пользователей с качеством отдельных когорт.

Что проверить отдельно:
- как именно ваша компания считает retention;
- какие события считаются возвратом;
- на каком интервале сравниваются когорты.
```

### One-screen learning loop

```text
Рабочий learning loop с AI:
1. объясни простым языком;
2. сравни с похожим понятием;
3. задай мне вопросы;
4. проверь мой ответ;
5. скажи, что проверить отдельно.
```

## 3. Урок 22: L22-CASE-A и L22-CASE-B. Игрушка vs инструмент

### L22-CASE-A. Интересно, но бесполезно

Сценарий:
- человек просит AI придумать 20 необычных названий для внутренней еженедельной встречи команды;
- команда не использует эти названия;
- в процесс это никак не встраивается;
- повторяемости и эффекта нет.

Формулировка:

```text
Придумай 20 креативных названий для нашей внутренней планерки.
```

Почему это игрушка:
- нет повторяемого рабочего эффекта;
- нет измеримой экономии времени;
- нет улучшения качества результата;
- нет влияния на реальный процесс.

### L22-CASE-B. Просто, но полезно

Сценарий:
- после каждого клиентского созвона менеджер отправляет follow-up;
- раньше на это уходило 8-10 минут;
- теперь AI помогает сделать черновик за 2-3 минуты;
- менеджер вручную правит и отправляет письмо;
- письма стабильно уходят в течение 30 минут после встречи.

Полезный prompt:

```text
Подготовь короткое follow-up письмо после клиентского созвона.

Контекст:
- я account manager;
- нужно зафиксировать 3 договоренности и следующий шаг;
- письмо должно быть коротким и деловым;
- нельзя добавлять обещания, которых не было на встрече.
```

### Таблица сравнения

| Критерий | CASE-A: названия для встречи | CASE-B: follow-up после созвона |
|---|---|---|
| Повторяемость | низкая | высокая |
| Ясность результата | низкая | высокая |
| Измеримый эффект | нет | да |
| Встраиваемость в процесс | нет | да |
| Стоит внедрять | нет | да |

### Practical filter

```text
Фильтр полезности сценария:
1. задача повторяется;
2. результат понятен;
3. эффект можно заметить или измерить;
4. без AI работа реально медленнее или тяжелее;
5. сценарий можно повторить завтра без героизма.
```

### One-screen scoring table

| Вопрос | Да / Нет |
|---|---|
| Это повторяется хотя бы несколько раз в неделю? |   |
| Результат можно быстро оценить? |   |
| Есть экономия времени или снижение трения? |   |
| Это можно встроить в реальный процесс? |   |
| Я готов повторить это завтра? |   |

### Decision rule

```text
Если у сценария 4-5 ответов "да", это кандидат на внедрение.
Если 2-3, это сценарий на тест.
Если 0-1, это пока игрушка.
```

## 4. Урок 23: L23-CASE-A. Личная AI-система

### Логика системы

У личной системы должно быть 5 блоков:
1. сценарии;
2. шаблоны;
3. чек-лист проверки;
4. правила безопасности;
5. журнал подтверждений.

### Минимальная структура хранения

Можно хранить в:
- одной таблице;
- одном документе;
- одном workspace в Notion;
- одной папке в Google Docs.

Главный критерий:
- система должна помогать повторять удачные сценарии, а не выглядеть красиво.

### Таблица личной системы

| Блок | Что хранится | Пример |
|---|---|---|
| Сценарии | список повторяющихся задач | follow-up после встречи; summary документа; внутреннее сообщение |
| Шаблоны | лучшие prompts и заготовки | prompt на follow-up; prompt на summary; prompt на tone-edit |
| Проверка | короткий quality checklist | факт; контекст; тон; следующий шаг; лишние обещания |
| Безопасность | правила, что нельзя отправлять в AI | персональные данные; конфиденциальные цифры; неанонимизированные договоры |
| Proof log | что реально сработало | сценарий; дата; эффект; оставшийся риск |

### Заполненный пример

| Сценарий | Где использую | Шаблон | Чек-лист | Статус |
|---|---|---|---|---|
| Follow-up после встречи | после клиентских звонков | `followup_v2` | факт / тон / action | рабочий |
| Summary документа | внутренние 3-5 стр. документы | `summary_ops_v1` | точность / цифры / смысл | на тесте |
| Внутреннее сообщение | согласование и напоминания | `message_tone_fix_v1` | ясность / срок / адресат | рабочий |

### L23-BRIDGE-A. Из личного в командное

Самый короткий путь из личной системы в командную:
- выбрать один общий сценарий;
- выбрать один общий шаблон;
- выбрать один общий чек-лист проверки;
- назначить owner;
- собирать 2-3 proof examples.

### One-screen team proof path

```text
Командный proof path:
1. один общий сценарий;
2. один общий шаблон;
3. один общий чек-лист;
4. один owner;
5. 2-3 примера использования;
6. одна метрика поведения или экономии времени.
```

### One-screen личная система

```text
Моя AI-система:
- 3-5 рабочих сценариев;
- библиотека шаблонов;
- чек-лист проверки;
- правила безопасности;
- журнал подтверждений лучших кейсов.
```
