## 2. Урок 12: CM-L12-CASE-A

### Задача

Проверить AI-summary по заметкам после операционной встречи о запуске пилота.

### Исходные заметки

```text
Операционный синк по пилоту:
- запуск в понедельник возможен только если DPA согласован юристами до пятницы 17:00;
- финальный список из 12 пользователей нужен до четверга 16:00;
- support должен подготовить FAQ к пятнице 12:00;
- клиент просит еженедельный статус каждый четверг;
- 2 магазина еще не передали корректные таблицы остатков;
- без этих таблиц подключение всех точек в понедельник под риском.
```

### AI-summary для проверки

```text
Пилот стартует в понедельник.
Клиент будет получать еженедельный статус по четвергам.
FAQ можно спокойно завершить после запуска, это не блокирует процесс.
Список пользователей желательно финализировать на следующей неделе.
Основной риск сейчас в нагрузке на support, но запуск в целом выглядит стабильным.
```

### Быстрый разбор, что не так

| Критерий | Что проверяем | Что ломается в примере |
|---|---|---|
| Факты | точные сроки, числа, условия | потерян срок по списку пользователей и условие про DPA |
| Логика | выводы следуют из исходника | summary звучит уверенно, хотя в исходнике есть блокеры |
| Полнота | сохранены ли критичные зависимости | выпал риск по 2 магазинам и таблицам остатков |
| Тон | не создает ли текст ложного спокойствия | тон слишком успокаивающий для рискованной ситуации |
| Применимость | можно ли это переслать как есть | нет, руководитель получит искаженный статус |
| Риск | цена ошибки при использовании | можно пообещать запуск без готовности |

### Корректная версия summary

```text
Запуск пилота в понедельник возможен только если DPA будет согласован до пятницы 17:00.
Финальный список из 12 пользователей нужен до четверга 16:00.
Support должен подготовить FAQ к пятнице 12:00.
Клиент просит еженедельный статус каждый четверг.
Отдельный риск: 2 магазина еще не передали корректные таблицы остатков, поэтому подключение всех точек в понедельник пока не гарантировано.
```

### One-screen checklist

```text
Чек-лист проверки AI-ответа:
1. Факты: даты, числа, условия точны?
2. Логика: выводы реально следуют из исходника?
3. Полнота: не выпал ли критичный контекст?
4. Тон: текст не создает ложной уверенности?
5. Применимость: можно ли это реально отправить или использовать?
6. Риск: что случится, если здесь ошибка?
```

### Verification prompts

#### Prompt 1. Быстрая проверка summary

```text
Сопоставь summary с исходными заметками.
Найди:
- потерянные сроки;
- потерянные условия;
- ложные или слишком широкие выводы;
- блокеры, которые выпали из текста.
Ответ дай в таблице: проблема / где именно / почему это риск.
```

#### Prompt 2. Проверка на ложное спокойствие

```text
Посмотри на этот рабочий summary как на текст для руководителя.
Скажи:
- где тон создает ложное ощущение, что все под контролем;
- какие места нужно усилить фактами и условиями;
- какие риски должны быть проговорены явно.
```

## 3. Урок 13: CM-L13-RISK-MAP и CM-L13-CASE-A

### Green / Yellow / Red map

| Зона | Что можно делать | Правило |
|---|---|---|
| Зеленая | идеи заголовков, черновик структуры, summary публичной статьи, черновик внутренней заметки без чувствительных данных | использовать как быстрый черновик |
| Желтая | follow-up письмо клиенту, summary рабочей встречи, action items, draft FAQ, внутренняя status note | использовать только после внимательной проверки |
| Красная | обещание скидки или срока запуска клиенту, юридические формулировки, чувствительные данные, персональные данные, управленческие выводы по непроверенным цифрам | нельзя копировать как есть; нужен жесткий human review или отдельный policy gate |

### Красная зона: CM-L13-CASE-A

#### Ситуация

Менеджер хочет быстро ответить клиенту после сложного звонка.

Что реально известно:
- скидка 15% не согласована;
- юридический отдел еще не подтвердил дату запуска;
- клиент просит письменное подтверждение сроков.

#### Небезопасный prompt

```text
Напиши клиенту письмо после звонка.
Скажи, что мы дадим скидку 15% и запустимся до 1 апреля.
Сделай письмо уверенным и спокойным.
```

#### Опасный AI-ответ

```text
Подтверждаем, что готовы предоставить скидку 15% и выйти в запуск до 1 апреля.
Команда уже завершает финальные приготовления, поэтому со своей стороны рисков не видим.
```

#### Почему это красная зона

1. Здесь есть внешнее обещание клиенту.
2. Здесь есть коммерческое условие.
3. Здесь есть срок, который еще не подтвержден.
4. Цена ошибки сразу репутационная и финансовая.

### One-screen framework для урока 13

```text
Разметка задач по риску:
Зеленая = быстрый черновик
Желтая = только после проверки
Красная = без копипаста и без ручного подтверждения не использовать
```

### Шаблон разметки задач по зонам

```text
Сценарий:
Аудитория:
Есть ли внешнее обещание:
Есть ли цифры / сроки / чувствительные данные:
Цена ошибки:
Зона:
Правило использования AI:
```

## 4. Урок 14: CM-L14-CASE-A

### Задача

Превратить сырой AI-черновик внутреннего status update в рабочий текст для руководителя проекта.

### Исходные факты

```text
Первая неделя пилота:
- подключены 3 магазина;
- еще 2 магазина ждут корректные таблицы остатков;
- support получил 14 вопросов, чаще всего про доступ;
- расширение scope не подтверждено, ждем юристов;
- в пятницу нужно принять решение, идем ли во вторую волну.
```

### Сырой AI-черновик

```text
Хочу поделиться обновлением по пилоту. На первой неделе у нас уже есть хороший прогресс, потому что часть магазинов подключена и команда активно отвечает на возникающие вопросы. Сейчас есть отдельные организационные моменты, связанные с таблицами остатков и юридическим согласованием дальнейшего расширения, но в целом работа идет в позитивной динамике. Мы соберем дополнительную информацию и к пятнице сможем принять решение о следующих шагах.
```

### Финальная версия после доработки

```text
Статус пилота за первую неделю:

- подключены 3 магазина;
- еще 2 магазина не готовы: ждем корректные таблицы остатков;
- support получил 14 вопросов, чаще всего по доступу;
- расширение scope пока не подтверждено: ждем ответ юристов;
- в пятницу принимаем решение, идем ли во вторую волну.
```

### Что именно изменили

| Шаг | Что сделали | Зачем |
|---|---|---|
| Сократили воду | убрали общие слова про "хороший прогресс" и "позитивную динамику" | чтобы текст не маскировал статус |
| Вернули факты | перечислили магазины, вопросы и зависимость от юристов | чтобы руководитель видел реальную картину |
| Выделили блокеры | отдельно показали 2 магазина и юристов | чтобы решение не было принято вслепую |
| Довели формат | сделали короткий status update списком | чтобы текст можно было быстро читать и использовать |

### One-screen framework для урока 14

```text
5 движений до рабочего результата:
1. убрать воду;
2. вернуть факты;
3. выделить блокеры;
4. адаптировать под адресата;
5. довести до формата задачи.
```

### Reusable prompt

```text
Улучши рабочий черновик.

Требования:
- не добавляй новые факты;
- убери воду и общие слова;
- верни точные сроки, цифры и условия;
- выдели блокеры отдельно;
- подстрой текст под формат короткого status update для руководителя.
```

## 5. Урок 15: CM-L15-CASE-A и CM-L15-RULESET-A

### Небезопасная постановка задачи: CM-L15-CASE-A

```text
Проанализируй обращение клиента Ивана Петрова.
Номер договора: 54821.
Телефон: +7 9XX XXX XX XX.
Сумма спорного возврата: 184 500 рублей.
Подскажи, как лучше ответить клиенту и кто из команды виноват.
```

### Безопасная постановка той же задачи

```text
Проанализируй обезличенное обращение клиента по спорному возврату.

Контекст:
- клиент недоволен сроком обработки возврата;
- в процессе было несколько внутренних передач между отделами;
- нужно подготовить спокойный и деловой ответ клиенту;
- персональные данные, номер договора и точные чувствительные детали убраны.

Нужно:
- назвать 2-3 вероятные причины проблемы;
- предложить структуру ответа клиенту;
- перечислить, какие факты нужно подтвердить вручную до отправки ответа.
```

### 5 правил безопасной работы: CM-L15-RULESET-A

```text
1. Не вставляйте персональные данные, если без них можно решить задачу.
2. Не передавайте номера договоров, финансовые детали и чувствительные условия без явной необходимости и понимания политики.
3. Лучше кратко пересказать документ, чем вставлять его целиком.
4. Перед отправкой спросите себя: какой минимальный контекст нужен модели?
5. Если цена утечки или ошибки высокая, сначала смотрите на корпоративные правила, а не на удобство.
```

### One-screen do / don't

| Делать | Не делать |
|---|---|
| обезличивать | вставлять ФИО, телефоны, номера договоров |
| передавать минимум контекста | загружать весь документ целиком "потому что быстрее" |
| просить структуру и варианты | просить модель принять решение вместо вас |
| отдельно проверять чувствительные выводы | слепо копировать ответ во внешнюю коммуникацию |

### Микро-мост к manager/company layer

```text
Личная цифровая гигиена сотрудника потом превращается в:
1. правило команды;
2. manager checklist;
3. company policy.
```
