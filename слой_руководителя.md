# Слой руководителя

Дата: 22 марта 2026
Статус: concrete-first operating pack для руководителя B2B-пилота

## 1. Что получает руководитель

Руководитель должен выйти не с общим пониманием AI, а с четырьмя готовыми артефактами:
1. baseline card по одной команде и одному shared scenario;
2. manager scorecard с логикой `green / yellow / red`;
3. decision memo по итогам пилота;
4. 14-дневный rollout board на следующую волну.

Если этих четырех артефактов нет, слой руководителя еще не собран.

## 2. Обязательные решения до старта

До kickoff руководитель обязан зафиксировать:
1. одну функцию или одну команду;
2. одного owner со стороны бизнеса;
3. один shared scenario для пилота;
4. период baseline на `5-10` рабочих дней;
5. список разрешенных green-zone сценариев;
6. список red-zone исключений;
7. даты kickoff, midpoint-check и final review.

Launch gate для руководителя:
- нет owner = не запускаем;
- нет shared scenario = не запускаем;
- нет baseline = не считаем ROI и не обещаем scale;
- нет review cadence = не продаем `Pilot Plus`.

## 3. Шаблон 1. Baseline Card руководителя

### Карточка пилота

```text
Пилот:
Функция / команда:
Business owner:
Руководитель группы:
Shared scenario:
Период baseline:
Период пилота:
Размер группы:
Источник данных:
Что считаем успехом к дню 14:
```

### Таблица baseline

| Линия | Метрика | Как считать | База | Цель к финалу | Источник | Владелец |
|---|---|---|---:|---:|---|---|
| Активация | Start rate | `стартовали / включены в группу` |  | `>= 85%` | LMS / cohort list | owner |
| Активация | Session 0 completion | `прошли Session 0 / стартовали` |  | `>= 75%` | LMS | owner |
| Early value | First win rate | `зафиксировали first win / стартовали` |  | `>= 65%` | форма фиксации wins | руководитель |
| Повторяемость | Shared scenario usage | `участники, применившие общий сценарий >= 2 раз / стартовали` |  | `>= 60%` | выборка артефактов | руководитель |
| Повторяемость | Template adoption | `участники, использующие общий шаблон / стартовали` |  | `>= 70%` | шаблоны / CRM / docs | руководитель |
| Скорость | Cycle time на кейс | `сумма минут по кейсам / число кейсов` |  | `-20% и лучше` | CRM / задачи / self-report | owner |
| Качество | First-pass quality rate | `кейсы без существенной переделки / все кейсы` |  | `>= 80%` | выборка `15-20` кейсов | руководитель |
| Качество | Rework rate | `кейсы с повторной правкой / все кейсы` |  | `-20% и лучше` | выборка кейсов | руководитель |
| Риск | Safety incidents | число реальных нарушений |  | `0` | ручной разбор | owner |
| Управление | Owner readiness | `готов / условно готов / не готов` к wave 2 |  | `готов` | финальный review | business owner |

### Правила заполнения baseline

1. База берется только по одному shared scenario, а не по всей функции сразу.
2. Если нет цифровой базы, используйте ручную выборку `15-20` кейсов.
3. Для скорости считаем медиану или среднее в минутах, а не самоощущение команды.
4. Для качества используем короткий чек-лист: фактология, полнота, тон, следующий шаг, риск.
5. Если baseline собран на разных сценариях, scorecard считается недостоверным.

## 4. Шаблон 2. Manager Scorecard

| Линия | Метрика | База | Текущее | Green | Yellow | Red | Статус | Что делаем |
|---|---|---:|---:|---|---|---|---|---|
| Активация | Start rate |  |  | `>= 85%` | `70-84%` | `< 70%` |  |  |
| Активация | Session 0 completion |  |  | `>= 75%` | `55-74%` | `< 55%` |  |  |
| Early value | First win rate |  |  | `>= 65%` | `45-64%` | `< 45%` |  |  |
| Повторяемость | Shared scenario usage |  |  | `>= 60%` | `40-59%` | `< 40%` |  |  |
| Повторяемость | Template adoption |  |  | `>= 70%` | `50-69%` | `< 50%` |  |  |
| Скорость | Cycle time delta |  |  | `<= -20%` | `-10% ... -19%` | `> -10%` |  |  |
| Качество | First-pass quality rate |  |  | `>= 80%` | `65-79%` | `< 65%` |  |  |
| Качество | Rework rate delta |  |  | `<= -20%` | `-10% ... -19%` | `> -10%` |  |  |
| Риск | Safety incidents |  |  | `0` | `1 исправленный` | `2+ или 1 серьезный` |  |  |
| Решение | Owner readiness |  |  | `готов scale` | `готов после правок` | `не готов` |  |  |

### Быстрая логика решения по scorecard

- `scale`: нет red по рискам, минимум `6` green-метрик, template adoption `>= 70%`, owner readiness = `готов scale`.
- `improve`: нет red по рискам, минимум `3` green-метрики, есть рабочий shared scenario, но до нормы команды не дотянули.
- `narrow`: польза есть на одном сценарии или одной роли, но не на всей группе.
- `stop`: есть red по рискам, нет owner, нет общего сценария или нет правдоподобного сигнала эффекта.

## 6. Шаблон 4. 14-дневный rollout board руководителя

| День | Действие руководителя | Действие команды | Артефакт дня | Если не выполнено |
|---|---|---|---|---|
| `D0` | подтвердить owner, группу, scenario, baseline | получить kickoff packet | baseline card v1 | пилот не стартует |
| `D1` | провести kickoff `20 мин` | пройти onboarding | список участников и правила | режем scope |
| `D2` | проверить Session 0 completion | пройти Session 0 | first wins v1 | owner push |
| `D3` | утвердить shortlist кейсов | сделать 1 кейс на shared scenario | use-case shortlist | убираем лишние сценарии |
| `D4` | выбрать template owner | собрать общий шаблон v1 | shared template v1 | назначаем одного автора |

| `D6` | провести midpoint-check | показать кейсы и трения | midpoint scorecard | narrowing |
| `D7` | принять решение по scope | продолжить только green/yellow use cases | scope decision | стоп по red use cases |
| `D8` | снять операционные блокеры | дособрать недостающие артефакты | blockers log | escalation owner |
| `D9` | утвердить checklist v1 | применять checklist на кейсах | shared checklist v1 | ручной ревью-режим |

## 7. Ритм встреч руководителя

### Kickoff, `20 минут`

1. Подтвердить owner и shared scenario.
2. Подтвердить green / yellow / red зоны.
3. Зафиксировать baseline и review dates.
4. Назначить ответственных за template и checklist.

### Midpoint-check, `20 минут`

1. Смотрим только `5` сигналов: Session 0, first win, shared scenario usage, template v1, risk log.
2. Решаем одно из трех: `continue / narrow / convert to QA`.
3. Режем все, что не дает сигнала к финалу.

### Final review, `30 минут`

1. Сравниваем baseline и финал.
2. Показываем `1` общий сценарий, `1` общий шаблон, `1` чек-лист, `1` proof case.
3. Принимаем одно решение и сразу назначаем владельца на следующие 14 дней.

## 8. Когда этот файл считается готовым

Файл готов, если руководитель может без внешнего консультанта:
1. назвать одну управляемую pilot unit;
2. показать baseline и финал по одной таблице;
3. принять решение без фразы `в целом было полезно`;
4. перевести решение в 14-дневный план с владельцами.
